## 2. Data safety for the operator's only database: PASS

The store uses the default rollback journal (no WAL pragma anywhere), so there are no sidecars and the `busy_timeout(2s)` waits out an engine write.

A Rust error becomes nil/false, and a panic is caught by uniffi's scaffolding and thrown as an internal error, which `try?` also absorbs. No crash path. If `VACUUM INTO` fails part-way, the URL is not appended (`VaultExport.swift:23-24`), so a partial file is never handed to the share sheet. If the .md succeeds and the copy fails, the sheet offers just the .md, which is acceptable.

## 4. Export correctness: PASS

- **Hand-check against the schema** (`migrations.rs:13-79`). Every fixture INSERT column exists with the right nullability (`export.rs:381-456`).
  - Session `ses-1`: `thread_id` → `thr-entropy` (and `thread_prompt` resolves to it), `turns: 2` from `transcript::parse`. The note and then the trace come before the transcript, matching spec item 8.
  - Salt `rz-1` → `thread_id thr-entropy`, `child_thread_id thr-child`, domains via `realization_domains`.
  - Child thread: `parent_realization_id "rz-1"`, derived `parent_thread_id "thr-entropy"`. The parent shows `child_thread_ids ["thr-child"]`.
  - Tending `2026-07-14 · 20 · ["thr-entropy"]`.
  - Epochs: 1784019600 = 2026-07-14T09:00Z (day 20648 × 86400 + 9 h) and 1783843200 = 2026-07-12T08:00Z. `iso_utc` is independently pinned at epoch 0.
- **Ordering:** every new reader ends in `id ASC` (domains, pull notes, threads, sessions, notes, traces). Exceptions: tending orders by its PK `day`, profile by its PK `section`, and kindling by `(first_kindled_at, passage_key PK)`, all total orders. `list_realizations` gained `id ASC` (`realizations.rs:217`). Child ids are sorted `(created_at, id)` (`export.rs:193-204`). HashMaps are lookups only, never iterated for output.
- **Timestamps:** the only clock-derived field is `exported_at = self.now()` (`export.rs:127`). It is injectable and the tests fix it, so there are no other export-time stamps in the document. The Swift *file name* carries a local `yyyy-MM-dd` (`VaultExport.swift:16-17`), which is fine.
- **CLI** (re-run by me): a missing db prints `athanor-cli: not found: store file …/missing.sqlite`, exits 1, and creates no file. An existing `--out` is refused with exit 1 and the file is unchanged (0 bytes). The normy export has 9 sections, `counts: {… threads: 22, realizations: 8, … sessions: 0 …}`, and `shasum -c` gives **OK** (the source is byte-unchanged).
  - *nit N3:* the `--out` existence check (`main.rs:157`) is check-then-`fs::write`, a TOCTOU race. `OpenOptions::create_new` would close it. This is a dev tool, so it is harmless.
- *nit N4 (spec drift, documented lossiness):* bodies are "verbatim" per the spec, but notes, traces and turns are `.trim()`ed on both ends (`export.rs:275,278,291`) and record bodies are `trim_end`ed (`:58`). Leading and trailing whitespace is lost. The `.sqlite` copy stays lossless, so this is acceptable for v1; note it in the format spec.

### should-fix S1: the long-press and dismiss paths were never exercised

BUILD-LOG Task 10 says steps 5 (dismiss → tmp cleanup) and 6 (manual long-press, tap and swipe regression) were **not done**. Only the `export-vault=1` QA hook path is proven. The operator is the first human to long-press, on the device that holds the only DB.

The risk to data is nil: the path is read-only. The risk is that the door "doesn't open" on the day it is needed. Ask the operator to do step 6 on a **simulator or a second build first**, or accept it consciously. If the gesture fails on device, the QA hook cannot rescue him, because TestFlight cannot pass launch args.

### should-fix S2: share-sheet completion may leave a blank sheet and skip cleanup

`ShareSheet` sets no `completionWithItemsHandler` (`ShareSheet.swift:6-9`). After a completed AirDrop, `UIActivityViewController` dismisses its own content. Inside a SwiftUI `.sheet` this commonly leaves an **empty sheet** that the user must swipe away. `onDismiss` (and so `VaultExport.cleanUp()`) only runs then.

This is functionally fine but looks broken, and it is untested (see S1). Fix in a follow-up: in the completion handler, set `vaultShare = nil` (pass a closure in), which also triggers cleanup.

### nit N6: the export runs synchronously on the main thread

`beginVaultExport` (`FurnaceScreen.swift:98-102`) runs `export_vault` + `VACUUM INTO` synchronously on the main thread, and the 2 s busy-timeout can add to that if the engine is mid-write. For one person's store (the sim smoke: 24 KB md + 100 KB db) this is milliseconds. Move it to a detached task only if the store grows.
