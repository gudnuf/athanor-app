## 2. What can and cannot be backfilled

| Link | Backfilled by v3? | How / why not |
|---|---|---|
| session minutes | **Yes**, for closed sessions **with a `◇ LEARNER` block** | `ceil((ended_at − started_at)/60)`, clamped to [1, 60]. This is the wall-clock span: `mark_session_ended` overwrote `updated_at`, so the last-activity time is lost. |
| session tended day | **Yes**, same filter | the UTC day of `ended_at`, if that day has a tending row |
| tending minutes | **Yes**, where `minutes = 0` | the sum of that day's backfilled session minutes |
| session ↔ child born of a salt | **Yes** | the realization's `created_at` falls inside the latest-started closed session |
| session ↔ thread opened in-session | **Yes** | `threads.born` falls inside it, for threads with no `parent_realization_id` |
| tending thread_ids | **Yes**, where `'[]'` and links exist | the distinct thread ids linked to that day's sessions |
| thread last_worked | **Yes**, where linked | `MAX(ended_at)` over its links |
| child thread domain | **Yes**, where null | the parent realization's **first-inserted** domain (`ORDER BY rd.rowid`), matching S5's `domain_names[0]` going forward |
| session ↔ thread a salt *fixed* | **No** | `realizations.thread_id` is known to be wrong in field data |
| wrongly fixed parent threads | **No** | realizations are immutable and `fixed` is terminal. A repair would be a later door the learner opens. |
| domain of a thread with no salt lineage | **No** | no stored signal. Going forward this comes from S5 and S7. |
| what a threadless session discussed, when it called no tool | **No** | it lives only in prose |
| inflated tending days | **No** | a tending row can't tell which session made it. The fix applies going forward (S3). |
| a salt fixed in an abandoned session that overlaps a closed one | misattributed | the closed session gets the `born` link. This is rare and accepted (see Risks). |

**Invariant #5 (fire is append-only).** v3 *writes* to `tending`: it sets
`minutes` only where it is 0 and `thread_ids` only where it is `[]`. It never
inserts or deletes a day and never touches `created_at`. This corrects a
placeholder value; it does not rewrite history. The commit message says so in
those words.

```sql
ALTER TABLE sessions ADD COLUMN minutes INTEGER;
ALTER TABLE sessions ADD COLUMN tended_day TEXT;
CREATE TABLE session_threads (
  session_id TEXT NOT NULL REFERENCES sessions(id),
  thread_id  TEXT NOT NULL REFERENCES threads(id),
  role TEXT NOT NULL,          -- focal|worked|opened|fixed|born|evaporated
  created_at INTEGER NOT NULL,
  PRIMARY KEY (session_id, thread_id, role));
UPDATE sessions SET minutes = MAX(1, MIN(60, (ended_at - started_at + 59) / 60))
  WHERE state = 'closed' AND ended_at IS NOT NULL AND transcript LIKE '%◇ LEARNER%';
UPDATE sessions SET tended_day = strftime('%Y-%m-%d', ended_at, 'unixepoch')
  WHERE state = 'closed' AND ended_at IS NOT NULL AND transcript LIKE '%◇ LEARNER%'
    AND strftime('%Y-%m-%d', ended_at, 'unixepoch') IN (SELECT day FROM tending);
INSERT OR IGNORE INTO session_threads (session_id, thread_id, role, created_at)
  SELECT id, thread_id, 'focal', started_at FROM sessions WHERE thread_id IS NOT NULL;
INSERT OR IGNORE INTO session_threads (session_id, thread_id, role, created_at)
  SELECT sid, child_thread_id, 'born', created_at FROM (
    SELECT r.child_thread_id, r.created_at,
      (SELECT s.id FROM sessions s WHERE s.state = 'closed'
         AND r.created_at BETWEEN s.started_at AND s.ended_at
         ORDER BY s.started_at DESC LIMIT 1) AS sid
    FROM realizations r WHERE r.child_thread_id IS NOT NULL) WHERE sid IS NOT NULL;
INSERT OR IGNORE INTO session_threads (session_id, thread_id, role, created_at)
  SELECT sid, id, 'opened', born FROM (
    SELECT t.id, t.born,
      (SELECT s.id FROM sessions s WHERE s.state = 'closed'
         AND t.born BETWEEN s.started_at AND s.ended_at
         ORDER BY s.started_at DESC LIMIT 1) AS sid
    FROM threads t WHERE t.parent_realization_id IS NULL) WHERE sid IS NOT NULL;
UPDATE tending SET minutes = (SELECT COALESCE(SUM(minutes), 0) FROM sessions WHERE tended_day = tending.day)
  WHERE minutes = 0;
UPDATE tending SET thread_ids = (
    SELECT json_group_array(DISTINCT st.thread_id) FROM session_threads st
    JOIN sessions s ON s.id = st.session_id WHERE s.tended_day = tending.day)
  WHERE thread_ids = '[]'
    AND EXISTS (SELECT 1 FROM session_threads st JOIN sessions s ON s.id = st.session_id WHERE s.tended_day = tending.day);
UPDATE threads SET last_worked = (
    SELECT MAX(s.ended_at) FROM session_threads st JOIN sessions s ON s.id = st.session_id
    WHERE st.thread_id = threads.id AND s.state = 'closed')
  WHERE last_worked IS NULL;
UPDATE threads SET domain_id = (
    SELECT rd.domain_id FROM realization_domains rd
    WHERE rd.realization_id = threads.parent_realization_id ORDER BY rd.rowid LIMIT 1)
  WHERE domain_id IS NULL AND parent_realization_id IS NOT NULL;
```

### S4. Thread handles, hardened

## 4. Release 2: the cold room

### The definition (revised anchor)

`Store::cold_domains(anchor: u64, window_days: u32, min_sessions: u32) -> Result<ColdReading>`
is pure over its arguments plus stored state. The Conductor passes
**`anchor = this session's started_at`**, which `create_session` writes before
any assemble (`conductor.rs:114`). Every reading is cached once per session.

- **Window** = the `window_days` UTC days ending on `today_utc(anchor)`, inclusive.
- Split it with `h = window_days / 2`:
  - **R** (recent) = the last `h` days ending on the anchor day;
  - **E** (earlier) = the `h` days before R.
  - Use an even `window_days`; 28 is.
- **A session touches domain d** if it is closed with `tended_day` set, and either:
  - (a) it has a `session_threads` link (any role except `evaporated`) to a thread with `domain_id = d`; or
  - (b) a realization whose `child_thread_id` is linked `born` in that session has `realization_domains` entry d.

  Count distinct sessions, bucketed by `tended_day`. The current session is open and never counts.
- **Evaporation time** = `today_utc(session_threads.created_at)` for links with `role = 'evaporated'`, written by S3's link write on `evaporate_thread`. Evaporations from before S3 left no link, so they are invisible. This errs toward speaking; the evaporated thread itself no longer counts toward any touch.
- **Per domain:**
  - **young**: `domain.created_at`'s day falls inside R.
  - **burning**: not young, with ≥ `min_sessions` touching sessions in R.
  - **cold**: not young; ≥ `min_sessions` touching sessions in E; 0 in R; and **no** thread in d has an evaporation day ≥ d's last touch day. Any single evaporated thread silences the whole domain, even if its other threads are open. This errs toward silence.
  - **quiet**: anything else. Never surfaced.
- **Reading:**
  - `Young` if fewer than K = 5 tending rows exist with `day ≤ anchor day`. K counts every tending row, including seeded and pre-fix days; seeded profiles have no sessions, so they read Young or Weak.
  - Otherwise `Strong { cold, burning }` when there is at least one cold and at least one burning domain. `cold` is ordered by oldest last touch, then name, at most 2. Each entry carries `name`, `last_touch_day` (**internal only**) and `last_salt: Option<String>`, the newest realization text in d.
  - Otherwise `Weak { burning }`.
- **Constants** in `store/cold.rs`: `COLD_WINDOW_DAYS = 28`, `COLD_MIN_SESSIONS = 2`, `COLD_MIN_TENDED_DAYS = 5`, `COLD_EVERY_N_SESSIONS = 5`.

**Worked example (hand-computed).** The session starts 2026-03-28T19:00Z, so the anchor day is 03-28. R = 03-15..03-28 and E = 03-01..03-14. There are 9 tending days (02, 05, 09, 12, 16, 19, 21, 24, 27), so the K check passes.

| domain | created | E sessions | R sessions | verdict |
|---|---|---|---|---|
| tides | 02-20 | 03-02, 03-05, 03-09 (salt "the tide waits for the moon") | — | **cold** |
| thermodynamics | 02-25 | 03-12 | 03-16, 03-19, 03-24 | **burning** |
| music | 03-20 | — | 03-21, 03-27 | **young** (created inside R; young wins over burning) |

→ `Strong { cold: [tides, salt "the tide waits for the moon"], burning: [thermodynamics] }`.

Variants:
- tides with only 03-09 → quiet → `Weak`;
- a 3-day practice → `Young`;
- a tides thread evaporated 03-10 → excluded → `Weak`;
- **the same store, with the session starting 2026-05-09** (six weeks away): R = 04-26..05-09 and E = 04-12..04-25 both hold 0 sessions, so nothing burns or goes cold → `Weak { burning: [] }`, and the Mystagogue says nothing. This is the case the anchor change exists for.

**The no-nag guard.** On the ambient path, a reading reaches the prompt only if:
- it is `Strong`; and
- at least `COLD_EVERY_N_SESSIONS` closed sessions with `tended_day` set have `started_at >` the `started_at` of the latest session with `cold_offered = 1` (or no session has been offered yet).

Otherwise the line is `(none — do not raise it)`. "Offered" is recorded when the line is *given*, which errs toward silence. The ask path (long-press) skips only the N-session limit, never the Young or evaporation rules, and also marks the session offered.

## 6. Risks

- **Honest-gap parents in the Grimoire.** Unresolved salts now land on `(the question this answered went unnamed)` threads. That is visible and repairable, and better than a lost salt or a wrong close. Count them in the next usage review; many of them means the handles aren't being used.
- **Handle collisions.** At 6 hex digits, about 3% of thousand-thread stores will have a collision somewhere. The ambiguity error covers it, and the fallback then makes an honest-gap parent, not a wrong bind.
- **Wall-span minutes**, clamped to 60 and measured to the last activity. They are never shown to the learner.
- **The backfill is heuristic.** It uses time-window joins. A salt fixed in an abandoned session that overlaps a closed one is credited to the closed one. Realizations and fixed-thread states are never touched.
- **The operator's store reads Young** until he has 5 tending days. That is the honest outcome.
