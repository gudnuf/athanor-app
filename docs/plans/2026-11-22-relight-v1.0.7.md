## Task 2: Pin the Mystagogue to `claude-opus-5-5`

**Today:** `apps/ios/Sources/Engine/RealEngineLoader.swift:52` passes `model: "claude-fable-5"`. The value flows through `TierConfig.model` (`crates/ffi/src/engine.rs:48`) into `build_engine` and then `GooseEngine::new(key, model, root)` (`crates/athanor-core/src/engine/goose.rs:75`). There `None` falls back to goose's `ANTHROPIC_DEFAULT_MODEL` (`claude-sonnet-4-5`).

**Change:** the model choice is domain configuration, so it moves into core (invariant #1). Swift passes `nil`, and core resolves `None` to `MYSTAGOGUE_MODEL`. A side benefit: the operator-run live tests can now exercise the exact id that ships. Today both live tests construct `GooseEngine::new(key, None, None)`, which silently tests sonnet-4-5 and not the shipped model.

**Goose compatibility check (done during planning, pinned rev 39c27c38 = tag v1.41.0):**
- **No allow-list rejects the id.** `ANTHROPIC_KNOWN_MODELS` (goose-providers `anthropic.rs:30`) feeds only the model listing. `claude-fable-5` is not in it either, and v1.0.5/1.0.6 worked.
- **The canonical registry** (`goose-provider-types/src/canonical/data/canonical_models.json`) has `anthropic/claude-fable-5` but **no `claude-opus-5-5`**. The registry is metadata only, but it changes the request shape:

  | Request field | fable-5 (v1.0.6) | opus-5-5 (v1.0.7) | Why |
  |---|---|---|---|
  | `max_tokens` | 4096 | 4096 | `GooseEngine` uses `ModelConfig::new` with no canonical limits, and `max_output_tokens()` defaults to 4096 |
  | `thinking` | `{type: adaptive}` + `output_config.effort: high` | **omitted** | `thinking_type_for_provider` needs `reasoning == Some(true)`, and that comes only from the canonical entry |
  | `temperature` | omitted (canonical `temperature: false`) | omitted (`ModelConfig::new` leaves it `None`) | |
  | `tool_choice` | not sent (auto) | not sent (auto) | |

- **API side:** Opus 5.5 with `thinking` omitted runs **adaptive** thinking at default effort **`medium`**. It rejects `budget_tokens`, `{type: disabled}`, `temperature`, and forced `tool_choice` with a 400, and goose sends none of these. So **no rejection is expected.** Two behavioral differences remain:
  - Effort drops from fable's `high` to `medium`.
  - Thinking tokens count against the same 4096 `max_tokens`, so long replies could end with `stop_reason: max_tokens`. That cap was already there under fable.
- **Traps to avoid** (corrected per review §3/N8; `formats/anthropic.rs` in the pinned checkout). No canonical `thinking_mode` exists for this id.
  - **(a)** `model_config.reasoning = Some(true)` **alone** is harmless. `effort` stays None and there is no `budget_tokens` param, so `effort.unwrap_or(Off)` → `Disabled` (`:108–118`).
  - **(b)** reasoning `Some(true)` **plus** a `thinking_effort` or `budget_tokens` request param → `ThinkingType::Enabled` → `{"type":"enabled","budget_tokens": min(16000, 4096−1024)=3072}` (`:638–650`). That **400s on Opus 5.5**.
  - **(c)** `AnthropicFormatOptions.preserve_thinking_context = true` injects `budget_tokens` even when the type is Disabled (`:654–666`). It is off today because `AnthropicProviderBuilder::new` uses `AnthropicFormatOptions::default()` (goose-providers `anthropic.rs:91`).
  - **(d)** `ModelConfig::with_temperature(..)`: `model_supports_temperature` defaults to `true` for unknown ids (`:82–86`), so the temperature would be **sent** and would 400.
  - `GOOSE_THINKING_EFFORT` is read only via `goose/src/model_config.rs:33`, which `GooseEngine` never calls, so it is inert on this path. Do not rely on it either way.
  - Raising effort or `max_tokens` is a follow-up lane, decided on live evidence, not in this release.

### Format spec (vault v1)

1. **Document header:** a YAML frontmatter block with the keys `athanor_vault: 1`, `exported_at`, `schema_version` (`PRAGMA user_version`), `device_id`, and `counts` (one flow map, fixed key order as in the example). Then `# Athanor vault`, then the fixed two-line intro paragraph.
2. **Sections, always all of them, in this order:** `## Profile`, `## Domains`, `## Pull notes`, `## Threads`, `## Realizations`, `## Correspondences`, `## Sessions`, `## Tending`, `## Kindling`. An empty section has the single line `_none_`.
3. **Record:** `### <heading>`, a blank line, `---`, then frontmatter lines `key: value` in the fixed key order shown, `---`, a blank line. Then the body (if any) verbatim, then a blank line.
4. **Value encoding:**
   - every string goes through `serde_json::to_string` (JSON strings are valid YAML double-quoted scalars, so escaping is handled);
   - `Option::None` → `null`;
   - integers bare;
   - lists as JSON arrays (`serde_json::to_string(&vec)`);
   - every timestamp as `iso_utc(..)`, quoted.
5. **Null rendering:** any absent value is the bare `null`. In particular:
   - a session with no thread → `thread_id: null`, `thread_prompt: null`;
   - a session whose `thread_id` points at a missing row → `thread_prompt: null`, with `thread_id` kept as stored;
   - a thread or pull note with no domain, or a domain id not in `all_domains` → `domain_id` as stored (or `null`) and `domain: null`;
   - a correspondence's `domain_a`/`domain_b` are free strings as the Mystagogue passed them to `weave_domains` (usually names) and are emitted as stored, never resolved.
6. **Headings by kind:**
   - profile → section name;
   - domain → name;
   - pull note → `pull · <id>`;
   - thread → first line of prompt, trimmed;
   - realization → `<YYYY-MM-DD of date> · <id>`;
   - correspondence → `<domain_a> ⟷ <domain_b>`;
   - session → `<iso started_at> · <mask>/<mode> · <id>`;
   - tending → day;
   - kindling → passage key.
7. **Thread `prompt:`** carries the full prompt (the heading is only its first line). **Derived thread fields:**
   - `parent_thread_id` = `realizations.thread_id` for `parent_realization_id`, or `null`;
   - `child_thread_ids` = the `child_thread_id`s of realizations whose `thread_id` = this thread, in `(created_at, id)` order, non-null only.
8. **Session body:**
   - every note as `#### Note · <iso created_at>` + text;
   - then every trace as `#### Trace · <iso created_at>` + text;
   - then `#### Transcript`, followed by each turn from `crate::transcript::parse(&session.transcript)` as `##### ◇ learner` or `##### ☿ mystagogue` + text;
   - frontmatter `turns:` = number of parsed turns.
9. Realization `domains:` uses the linked domain *names* (reuse `list_realizations`, which already joins them).
10. The document ends with exactly one `\n` (trim trailing whitespace, then push `'\n'`).
11. Thread state is written through `ThreadState::as_str()`. Known lossiness (review N6): `thread_from_row` coerces an unknown state string to `volatile`, so a corrupt row renders as volatile. The `.sqlite` copy stays lossless.
12. **Record shapes, with key order fixed.** All nine kinds are listed so nothing is left to infer:
    - `profile`: `kind, section, updated_at`; body = content.
    - `domain`: `kind, id, name, created_at, updated_at, deleted_at`; no body.
    - `pull_note`: `kind, id, domain_id, domain, created_at`; **body = text**.
    - `thread`: `kind, id, prompt, state, domain_id, domain, born, last_worked, parent_realization_id, parent_thread_id, child_thread_ids, created_at, updated_at, deleted_at`; no body.
    - `realization`: `kind, id, date, thread_id, child_thread_id, domains, created_at`; body = text.
    - `correspondence`: `kind, id, domain_a, domain_b, created_at`; **body = note**.
    - `session`: `kind, id, state, mask, mode, thread_id, thread_prompt, started_at, ended_at, created_at, updated_at, turns`; body per item 8.
    - `tending`: `kind, day, minutes, thread_ids, created_at`; no body.
    - `kindling`: `kind, passage_key, first_kindled_at, source_id`; no body.

    A body that is empty after trimming is omitted (the record ends at `---` + a blank line).

## Task 5: `Store::open_read_only` + `Store::export_database_copy()`

The brief proposed copying the SQLite file from Swift with `FileManager`. This plan deviates and uses `VACUUM INTO` in core:
- the copy is a transactionally consistent snapshot even if a write is in flight;
- it needs no WAL/sidecar handling;
- it keeps Swift logic-free.

The bundled SQLite is 3.46.0 (rusqlite 0.32.1 / libsqlite3-sys 0.30.1), which supports `VACUUM INTO` (3.27+).

`open_read_only` is the safety primitive (review S2/S6). Every export path opens the store through it:
- the FFI free functions (Task 7) run on the device's live file;
- the CLI (Task 6) runs on the operator's AirDropped copy.

It never migrates, never creates a file, and refuses a schema it does not exactly match.

**Files:**
- Modify: `crates/athanor-core/src/store/mod.rs` (`open_read_only`)
- Modify: `crates/athanor-core/src/store/export.rs` (`export_database_copy`)
- Modify: `crates/athanor-core/src/error.rs` (only if no existing variant fits; prefer `CoreError::BadState(String)` / `NotFound(String)`, which exist)

```rust
impl Store {
    /// Opens an EXISTING store file read-only for export. Never migrates, never
    /// creates. Errors: missing file → NotFound; `user_version` != MIGRATIONS.len()
    /// → BadState("schema vN, this build expects vM — export from a copy with a
    /// matching build"). Sets busy_timeout(2s) so a read during the live engine's
    /// short write transaction waits instead of failing.
    pub fn open_read_only(path: impl AsRef<std::path::Path>, device_id: impl Into<String>) -> Result<Self, CoreError>;

    /// Writes a consistent copy of the whole database to `dest` (must not exist).
    /// Works on a read-only connection.
    pub fn export_database_copy(&self, dest: impl AsRef<std::path::Path>) -> Result<(), CoreError>;
}
```

`open_read_only` implementation:

```rust
//! Store-only vault export (relight v1.0.7): works with no key and no engine —
//! the rescue path must never depend on LLM credentials.
use athanor_core::Store;
use crate::engine::EngineError;

/// The whole vault (vault v1 markdown) of the store file at `db_path`, opened read-only.
#[uniffi::export]
pub fn export_vault_at(db_path: String) -> Result<String, EngineError> {
    Store::open_read_only(&db_path, "export")
        .and_then(|s| s.export_vault())
        .map_err(|e| EngineError::Read(e.to_string()))
}

/// A consistent copy of the store file at `db_path`, written to `dest_path` (must not exist).
#[uniffi::export]
pub fn export_database_copy_at(db_path: String, dest_path: String) -> Result<(), EngineError> {
    Store::open_read_only(&db_path, "export")
        .and_then(|s| s.export_database_copy(&dest_path))
        .map_err(|e| EngineError::Read(e.to_string()))
}
```

  ```swift
  /// core-made db copy into a fresh temp dir and returns the files to share.
  /// No logic — core renders everything; this only names files and writes bytes.
  enum VaultExport {
      static var directory: URL {
          FileManager.default.temporaryDirectory.appendingPathComponent("vault-export", isDirectory: true)
      }

      static func prepare() -> [URL] {
          let fm = FileManager.default
          let dir = directory
          try? fm.removeItem(at: dir)
          guard (try? fm.createDirectory(at: dir, withIntermediateDirectories: true)) != nil else { return [] }
          let f = DateFormatter(); f.dateFormat = "yyyy-MM-dd"; f.locale = Locale(identifier: "en_US_POSIX")

          if let md = RealEngineLoader.exportVault(), let data = md.data(using: .utf8) {
              let u = dir.appendingPathComponent("athanor-vault-\(stamp).md")
              if (try? data.write(to: u)) != nil { urls.append(u) }
          }
          let db = dir.appendingPathComponent("athanor-\(stamp).sqlite")
          if RealEngineLoader.exportDatabaseCopy(to: db.path) { urls.append(db) }
          // Sizes only — never content (private learner data).
          let sizes = urls.map { (try? fm.attributesOfItem(atPath: $0.path)[.size] as? Int) ?? 0 }
          NSLog("[Athanor] vault export prepared: \(urls.count) file(s), bytes=\(sizes)")
          return urls
      }

      static func cleanUp() { try? FileManager.default.removeItem(at: directory) }
  ```

## Risks found during planning

1. **Opus 5.5 request shape differs from fable's.**
   - The pinned goose v1.41.0 has no canonical entry for the id, so the request carries no `thinking` field. Opus 5.5 then runs adaptive at default effort `medium` instead of fable's `high`, under the same 4096 `max_tokens`.
   - No 400 is expected. Quality, truncation, and silent refusals can only be judged live (the Task 2 operator gate).
   - The four goose traps (Task 2) are what would turn this into a 400.
2. **The live tests didn't test the shipped model.** Both used `GooseEngine::new(key, None, …)`, which is sonnet-4-5. Task 2 fixes that.
3. **CI has been red since 2026-07-08 on our own code**, not on anything upstream. `ddee7a9` added a clippy lint (exit 101), then `aa37e5f` added fmt drift (exit 1). The FlakeHub annotation is noise that also appears on green runs. Task 1 must land first, or "commit-on-green" means nothing in CI.
4. **The key was published in public artifacts** (v1.0.4–1.0.6, up to 30 days each). Task 0 stops this; rotation is recommended (operator). Rotation alone would strand the phone on the revoked key without Task 2 step 5's Keychain re-seed.
5. **Runner drift.** Xcode 26.2 may have left `macos-15`; this is the dry run's job. `@main` actions (nix-installer) can change under us, and pinning them is a follow-up.
6. **External-lane review delay** (Task 11, step 6.3).
7. **Data loss happens only if the operator deletes the app.** The mitigation is a Finder backup plus "do not delete". v1.0.7 adds **no migration**, and every export path is read-only.
8. **The key is still baked into the bundle**, unchanged from 1.0.6. That is acceptable for single-device dogfood only. With the artifact gone, the remaining exposure is the TestFlight build itself, which goes only to invited testers.
9. **`just bindgen-swift` is stale** (it writes to the wrong directory). The plan avoids it; fixing it is a follow-up.
