## 2. Bonus bugs

**Root cause 7 (days tended inflated): the mechanism is wrong, and so is the fix.**

The ordinary path is already guarded. Existing test `conductor.rs:972` `closing_a_session_with_no_turn_does_not_advance_wisdom` opens `Conductor::begin` and calls `close` with no turn. It asserts `wisdom_days == 0` and state `abandoned`.

The only open-plus-close path that tends without a learner word is **the initiation**, and that is deliberate. bba7487's own body says: *"A completed initiation (open_turn) and any real exchange still tend as before."* So the plan does not contradict bba7487's ordinary-path fix; it re-litigates its one stated exception.

Hermetic test sketch, all three against today's tree:
```rust
// (a) ordinary: already covered by conductor.rs:972: wisdom 0, abandoned. No inflation.
// (b) initiation, no learner word: today → wisdom 1 (by design, bba7487)
let mut c = Conductor::begin_initiation(store.clone())?;
c.open_turn(&MockEngine::new(vec![text_delta("Welcome."), TurnComplete]), &mut |_| {}).await?;
c.close(0)?;  assert_eq!(store.wisdom_days()?, 1);
// (c) the likely real inflator: a speech-path non-utterance counts as a learner turn
let mut c = Conductor::begin(store.clone(), "philosophus", "explain", None)?;
c.run_turn(&engine, Some("..."), &mut |_| {}).await?;
c.close(0)?;  assert_eq!(store.wisdom_days()?, 1);   // tends on dots
```
Case (c) is my inference. 93a9949 ("an empty turn is not a turn") says dots or nothing from the speech path reach the Mystagogue as turns. The field review the plan cites is not in the repo, so I can't confirm which source dominates.

**B3 (blocker): S3's `learner_turns == 0 → abandon` breaks an existing test and changes the initiation.**
- `conductor.rs:936` `closing_the_initiation_lights_the_furnace_passage` runs `open_turn` and then `close`, and asserts FURNACE is kindled.
- Under S3 that session abandons, and `abandon()` never reaches `kindle_passage("FURNACE")` (`:495`). The gate goes red at S3, and a learner who hears the opening and closes never lights the Furnace.
- **Fix:**
  - (i) Rewrite root cause 7 to name the real sources: pre-bba7487 July days, the initiation (deliberate), and contentless speech turns.
  - (ii) Count `learner_turns` only for `run_turn` turns whose text has at least one alphanumeric character.
  - (iii) Decide explicitly whether an initiation with no learner word should tend and kindle. If it should not, update `:936` in the same commit and say so. If it should, exempt `is_initiation`.
  - The cold-room session (C3) should follow the ordinary rule: heard but never answered means abandoned. That is fine.

**Root cause 8:** ✅ confirmed. S5's `thread` handle arg fixes it.

## 3. Migration v3

**Schema.** `session_threads(session_id, thread_id, role, created_at, PK(session_id, thread_id, role))`, plus `sessions.minutes INTEGER` and `sessions.tended_day TEXT`. It applies inside `migrate_with`'s `BEGIN…COMMIT` with the `user_version` bump. Re-running the raw SQL errors on the duplicate column, but `user_version` guards that, so the migration is idempotent in practice. `migrate_with` is private, and the plan's test lives in the same module, so the call compiles. The count test moves 12 → 13. Migration tests go 3 → 5 ✓.

**Worked example (constructed, hand-run in sqlite 3.50.6).** Day = 2024-10-04, B = 1728000000.

| Row | Data |
|---|---|
| A | closed, B+1000..B+1600 |
| X | **abandoned**, B+1500..B+1700 |
| C | closed, B+1550..B+2000 (overlaps A: mask churn) |
| G | closed **ghost**, B+5000..B+5010, empty transcript (a pre-abandon-routing empty close) |
| Threads | T0 (wrongly fixed parent); S (seeded, no session); O (born B+1200); P (born B+1560, inside A∩C); C1 (child of R) |
| Realization | R at B+1580 on T0; `realization_domains` inserted D2 then D1 |
| Tending | today (0, `[]`); yesterday (15, `[]`) |

Output:
```
A 10 2024-10-04 | X (null) | C 8 2024-10-04 | G 1 2024-10-04
session_threads: (C,C1,born) (A,O,opened) (C,P,opened)      -- no T0, no S, no X
tending 2024-10-04: minutes 19, ["O","C1","P"]   |  2024-10-03: 15, []  (untouched)
threads: C1.domain=D1, C1.lw=B+2000; O.lw=B+1600; P.lw=B+2000; T0/S lw NULL, T0 domain NULL
```
- **Double-linking cannot happen.** Each realization or thread picks `LIMIT 1` (latest-started closed session). P and R both fell in A∩C and went to C only. Abandoned X is excluded. Born children carry `parent_realization_id`, so they never also get `opened`.
- Minutes: A = ceil(600/60) = 10 and C = ceil(450/60) = 8 ✓. `json_group_array(DISTINCT …)` works.
- **S-5a (should-fix): ghost sessions are credited.** G (no transcript) got `tended_day` and 1 minute, and it inflates tending to 19. A ghost would also count as a "touching session" in C1 if it ever got a link. **Fix:** add `AND transcript LIKE '%◇ LEARNER%'` (the `transcript::format_block` marker) to the `minutes` and `tended_day` backfills.
- **S-5b:** the child-domain backfill uses `ORDER BY rd.domain_id`, which picked **D1**. The model listed D2 first, and S5 forward uses `domain_names[0]`. Use `ORDER BY rd.rowid` so history and going-forward agree.
- Nit: a salt fixed inside an abandoned session that overlaps a closed one is attributed to the closed one. That is rare; note it in Risks.

**Invariants.**
- **#4 ✅** v3 never touches `realizations`. The domain write is on `threads`, and S5's parent-domain set is on `threads` too.
- **#5 ⚠ acceptable, but say so in the invariants paragraph.** v3 rewrites `tending.minutes` (only where 0) and `thread_ids` (only where `[]`). It never deletes or inserts days, and it leaves `created_at` alone. That corrects a placeholder rather than rewriting history, but it is a write to the fire table and should be named as such. **Inflated days are not deleted** (§2 last row) ✓, and that is the right call.
- **#6 ✅** every new path still goes through `fix_salt`, so a child is always born.
- **#7 ✅** for links. ⚠ The synthesized opening turn is persisted as a `◇ LEARNER` block by `run_turn_inner` (`conductor.rs:240-249`). That is pre-existing for initiation; C3 extends it to the cold room, so `recall` and the export will show words the learner never said (nit N6).

**B1 (blocker, R1): v3 breaks the v1.0.7 store-only export for any store that hasn't migrated yet.**
- `Store::open_read_only` refuses unless `user_version == MIGRATIONS.len()` (`store/mod.rs:96-101`). Both FFI exports go through it (`ffi/src/export.rs:10,18`), including the **raw `.sqlite` copy**.
- On a keyless device, `tryRealEngine` returns nil, so nothing ever runs `migrate()`. A v1.0.7 store updated to v1.0.8 therefore stays at v2, and both the `.md` and the `.sqlite` export fail. The rescue door would be dead on exactly the device it exists for.
- The same happens on the Mac: a v1.0.8 CLI refuses an AirDropped v1.0.7 file. R2's v4 repeats all of this.
- The plan never mentions `open_read_only`.
- **Fix:**
  - `export_database_copy` must not schema-check at all (refuse only `> expected`).
  - `export_vault` either accepts `found <= expected`, rendering the absent v3 columns as missing, or `VACUUM INTO` a temp file and migrates and exports that copy.
  - Add a test: open a v2-only file read-only on the v3 build and export both.

**S-1 (should-fix): S1 alone fails the gate.** `store/testdata/vault_export_fixture.md:4` is `schema_version: 2`, and `export_vault_matches_snapshot` (`export.rs:466`) will fail as soon as v3 lands. Either bump the fixture in S1 or merge S6 into S1.

## 4. S5: binding and salt loss

The resolution order (uuid → handle → focal → the session's only opened/worked → `answers` → error) and deleting `ripe_threads(1)` are right. Focal is always None in the app (root cause 1), so in production this reduces to handle → only-opened → `answers` → error.

**B2 (blocker): with neither a handle nor `answers`, the learner's words are dropped.**
- The error returns as a tool value (`mod.rs:369-374`). The FFI fires the salt moment only on a successful `ToolResult` (`ffi/src/session.rs:374-380`), so nothing on screen shows the loss.
- A model that moves on loses the salt. That is worse than a wrong thread: a wrong thread is visible and repairable, a lost salt is neither.
- It is already true today when no thread is open (`fix_salt_with_no_open_threads_errors_crisply`, `mod.rs:509`).
- **Required:** when nothing resolves, fix on a **new parent thread** whose prompt is an honest gap (e.g. `(the question this answered went unnamed)`, which satisfies #7). Link it `fixed`, keep the spiral child (#6), and return `{realization_id, child_thread_id, note: "fixed on a new thread; open handles: …"}`.
- Invert `:509` as well. The handle-listing error then never drops words; it becomes an informational note.

**S-4 (should-fix): handle lookup hardening.**
- `id LIKE '%' || h` treats `_` and `%` in model input as wildcards. An empty or short `h` matches many threads, and `#` is not stripped.
- Validate `^#?[0-9a-f]{6}$`, then `WHERE substr(id, -6) = ?`.
- Also accept a `#handle` passed in the legacy `thread_id` field.
- Collision rate over 6 hex digits ≈ n²/(2·16.7M): about 3% at 1,000 threads. The ambiguity error covers it ✓.

S5's link writes in `Mystagogue::run` depend on `session_id`, which is `Some` for every Conductor session (`conductor.rs:153`) ✓.

## 5. Release 2: the cold definition

**Worked example, recomputed.**
- A = 03-28, window 28 → inclusive 03-01..03-28. h = 14: R = 03-15..03-28, E = 03-01..03-14.
- Tending days {02,05,09,12,16,19,21,24,27} = 9 ≥ K = 5.
- Tides (created 02-20, so not young): E 3, R 0 → **cold**.
- Thermodynamics: R 3 → **burning**.
- Music (created 03-20, inside R): **young**.
- → `Strong{cold:[tides], burning:[thermodynamics]}` ✓.
- Variants ✓: only 03-09 → E = 1 < 2 → quiet → `Weak`; 3 days old → `Young`; evaporated 03-10 ≥ last touch 03-09 → excluded → `Weak`.

**Edge cases.**
- **A domain evaporated after its last touch.** The verdict is right, but *how* evaporation time is known is unspecified. `threads` has no `evaporated_at`, and `updated_at` moves on later writes (`set_thread_domain_if_null`). **Fix:** use the `session_threads(role='evaporated').created_at` link, compared as a UTC **day** against `last_touch_day`, inclusive. The rule also excludes a domain when *any* one of its threads was evaporated, even if others stay open. That errs toward silence, which is fine; state it.
- **A learner with 4 tending days** → `Young` regardless of the per-domain math ✓. Note that K counts *all* tending rows, including seeded and pre-fix inflated days. Seeded profiles (`athanor-cli seed`) write tending with **0 sessions**, so they read Young or Weak forever. The C1 tests must seed sessions by raw SQL, as planned ✓.

**The no-nag guard.** Five closed, tended sessions since the last `cold_offered = 1`; marked when given; the ask path resets the counter. Test counts are 6 + 3 = 9 ✓. Define "since" as `started_at >` the offered session's `started_at`.

**Anchor-on-last-tending-day: change it.** A learner back after 6 weeks:
- Last tending day was 03-28, and they return on 05-09.
- A is still 03-28, so the reading is the stale `Strong`: "thermodynamics burning", six weeks after the last touch.
- If five sessions have passed since the last offer, it is offered on the very first session back, the most fragile moment.
- After that session closes, A = 05-09: R holds 1 session and E holds 0, so the next reading is `Weak`.
- Net effect: one *false* "burning" claim, delivered exactly at return.

**Does prompt assembly have no `now()` today?**
- ✅ Yes: there is no `now()` in `prompt/`, and every store read in `profile_injection` is clock-free.
- But the premise is weak:
  - (a) The session row (`started_at`) is written by `create_session` *before* `assemble` runs (`conductor.rs:114`). Anchoring on **this session's `started_at`** is pure over stored state, and the reading is cached once per session anyway.
  - (b) The prompt-smith's core ask #1 (`2026-11-24-prompt-pack-v1-core-asks.md`) already plans to pass the instant in (`assemble_with_clock(…, now, tz)`) so it can render `last_session_ago`.
- With a session-start anchor, a 6-week return puts every domain in neither E nor R, so the reading is `Weak` and the Mystagogue stays silent. That is the no-nag outcome the open question wants.
- **R2-2 (should-fix):** anchor on the session's `started_at`. The ask path with nothing burning needs a defined line.

**R2-7 (should-fix):** the injection renders `(last worked <day>; …)`. With `last_session_ago` arriving, that date invites the model to count ("a few weeks"), which is the nag C4 forbids. Keep `last_touch_day` internal and render only the name and their words.
